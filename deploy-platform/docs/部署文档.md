## 1. 你在装什么

平台分三层，缺一层就只能看页面、发不了版：

| 层 | 跑在哪 | 做什么 |
|----|--------|--------|
| 交互与编排 | 本仓库的前端 + 后端 | Web、AI 助手、流水线、审批、权限 |
| 数据 | MySQL、Redis、Elasticsearch（Compose 默认带上） | 业务库、定时触发、实时日志；构建 / AI 日志按日归档到 ES |
| 执行 | 各机器上的 `deploy-agent.jar` | 构建机编译打包；部署节点写站点、启停服务 |

构建机和部署节点**主动拉**任务，不必给平台开入站。平台必须能被这些机器访问（IP 或域名）。

Compose 还会起一个 **harness-runner**：只跑第三方 Agent 工具，只读、无特权、和后端走内部网。没它时第三方工具一律拒绝，不会退化到后端进程里执行。

## 2. 三种装法

| | A 本机开发 | B Compose 试用 | C 生产 |
|--|-----------|----------------|--------|
| 谁该用 | 改代码、看界面 | 完整试用、小团队先跑起来 | 对内部或公网提供服务 |
| 数据库 | SQLite 文件 | Compose 里的 MySQL 8 | 同一套 Compose，或自备 MySQL |
| Redis | 可不装（定时触发不生效） | Compose 里必填口令 | 必填口令，不要映射到宿主机 |
| Elasticsearch | 本机 9200 或暂空 | Compose 自带单节点 | 可用本栈，或在设置页改成自备集群 |
| 前端入口 | http://localhost:5173 | http://localhost:8000 | 反代后的 `https://你的域名` |
| 管理员口令 | 演示 `admin` / `admin123` | 仍可用演示值，立刻改密 | 必须设 `BOOTSTRAP_ADMIN_PASSWORD` |
| Agent | 可装本机当构建机 | 按下面第 7、8 节装 | 每台目标机一键脚本 |

不要把 A 的演示口令和 SQLite 直接当生产。

## 3. 机器、依赖、端口

### 3.1 平台机（跑 Compose 或本机前后端）

| 项 | 要求 |
|----|------|
| CPU / 内存 | 试用 2 核 4 GB 够（ES 堆默认 512 MB）；生产建议 4 核 8 GB 起 |
| 磁盘 | 系统盘 + **数据盘**。制品、插件包、Linux JDK 安装包在 `backend-data`，日志在 `es-data`，都会变大 |
| 软件（A） | Python 3.10+（推荐 3.11/3.12）、Node.js 18+、Git。Windows 用 `py`，不要用 `python3`（多半是 Store 重定向器） |
| 软件（B/C） | Docker Engine + Docker Compose v2 |
| 编译 Agent | 改了 `agent-java/src` 后需要 **JDK 8** 的 `javac`（见第 14 节） |

### 3.2 构建机 / 部署节点

| 角色 | 系统 | 必须有 |
|------|------|--------|
| 构建机 | Windows / Linux / macOS | JRE/JDK 8+；磁盘给工作空间（拉代码、编译产物） |
| Windows 节点 | Windows Server 2012 R2+ | **管理员** PowerShell；JRE 8+；只填站点目录进白名单 |
| Linux 节点 | systemd 的 Linux | **root** 跑安装脚本；可从平台下载 JDK 8（见第 9 节） |

节点**不编译、不拉代码、不跑任意脚本**。编译请装构建机。

### 3.3 端口（平台机）

| 端口 | 服务 | 默认是否打到宿主机 |
|------|------|-------------------|
| 8000 | 前端 Nginx（容器内 80） | 是。浏览器走这里 |
| 8080 | 后端 API | 是。Agent 也连这里。上了反代后可只对外暴露 443 |
| 8090 | harness-runner | **否**。只在 Compose 内部网 |
| 3306 | MySQL | **否**（生产）。调试才叠加 `docker-compose.debug.yml` |
| 6379 | Redis | **否**（生产）。同上 |
| 9200 | Elasticsearch | **否**（生产）。同上 |

防火墙：给浏览器和 Agent 放行 8000（或 443）以及它们实际连接的后端地址。不要把 3306、6379、8090、9200 暴露到公网。

## 4. A. 本机开发（SQLite）

适合改代码。不经过 Docker。Windows、Linux、macOS 步骤相同，只是激活虚拟环境的命令不同。

仓库根目录下面，业务代码在 `deploy-platform/`。

### 4.1 后端

```bash
git clone https://github.com/Ease1994/PekaFlowAI.git
cd PekaFlowAI/deploy-platform/backend

# Windows
py -m venv .venv
.venv\Scripts\activate

# Linux / macOS
python3 -m venv .venv
source .venv/bin/activate

pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8080
```

`--host 0.0.0.0` 必须加，否则虚拟机 / 局域网访问不到。首次启动会：

- 建 SQLite 文件 `deploy-platform/backend/deploy_platform.db`
- 生成 `deploy-platform/backend/data/.secrets.json`（JWT / AES / Runner 令牌，**不要提交 Git**）
- 创建管理员 `admin` / `admin123`，并在日志里警告这是演示口令

可选：复制 `backend/.env.example` 为 `backend/.env`。不配 `DATABASE_URL` 就用 SQLite。接口清单看登录后的「调用手册」，不必开 `/docs`。

仓库里的启动脚本（在 `deploy-platform/` 下执行）：

```bash
# Git Bash / Linux
bash scripts/start-backend.sh

# Windows CMD
scripts\start-backend.bat
```

### 4.2 前端

另开一个终端：

```bash
cd PekaFlowAI/deploy-platform/frontend
npm install
npm run dev -- --host 0.0.0.0
```

浏览器打开 http://localhost:5173 。Vite 会把 `/api` 代理到 `http://localhost:8080`，开发机不必配 CORS。

登录 `admin` / `admin123`。然后做第 6 节，否则助手不能对话。

### 4.3 切到本机 MySQL（仍是开发）

复制 `backend/.env.example` 为 `.env`，把 `DATABASE_URL` 改成你的库，例如：

```
DATABASE_URL=mysql+pymysql://root:你的口令@127.0.0.1:3306/deploy_platform?charset=utf8mb4
```

先建好空库 `deploy_platform`，utf8mb4。重启后端。

## 5. B. Docker Compose 完整栈

推荐给「先完整跑起来」和大多数自建。编排文件是 **`deploy-platform/docker-compose.yml`**，不是仓库根目录。

会启动：MySQL 8、Redis 7、Elasticsearch 8、secrets-init、backend、harness-runner、frontend。

### 5.1 一键启动

在仓库根目录：

```bash
bash deploy/pekaflow.sh install
```

没有 `.env` 时脚本会从 `.env.example` 复制一份，再 `docker compose up -d --build`。已有 `.env` 不会覆盖。

也可以自己准备文件：

```bash
cd PekaFlowAI/deploy-platform
cp .env.example .env
```

Windows 没有 `cp` 就复制文件。`.env` 必须和 `docker-compose.yml` 同级。**填了值的 `.env` 不要提交 Git。**

`.env.example` 已写好试用口令（MySQL `rp-mysql`、Redis `rp-redis`、管理员 `admin` / `admin123`）。复制后直接：

```bash
docker compose up -d --build
```

生产请改 `.env` 里每一项口令和密钥后再启动。`DATABASE_URL` 里的密码必须和 `MYSQL_ROOT_PASSWORD` **逐字相同**。已经在跑的数据卷改 MySQL / Redis 口令不会生效，要换就 `docker compose down -v` 后重来（库会清空）。**已经在跑的环境不要换 JWT / AES**，否则库里 Git 凭证解不开。迁机把 `.env` 一起带走。

可选：

```bash
# 浏览器跨域白名单，逗号分隔。Compose 下前端由 Nginx 同源反代 /api，一般不用填
CORS_ORIGINS=
```

### 5.2 看是否就绪

第一次会拉镜像、编前端、编后端，可能要几分钟：

```bash
docker compose ps
docker compose logs -f backend
```

后端日志出现建表 / 管理员就绪，且 `docker compose ps` 里 backend、frontend 为 healthy（或至少 running）后再打开浏览器。

入口：

- 前端：http://localhost:8000
- API：http://localhost:8080 （默认**不**开 `/docs`）
- 健康检查：`GET http://localhost:8080/api/v1/health` 应返回 `status: up`

### 5.3 调试才把数据库端口打到宿主机

生产不要用。需要本机客户端连 MySQL / Redis 时：

```bash
docker compose -f docker-compose.yml -f docker-compose.debug.yml up -d
```

此时 3306、6379、9200 出现在宿主机。用完关掉 debug 覆盖层。

### 5.4 数据落在哪

四个 Docker 卷：

| 卷 | 内容 |
|----|------|
| `mysql-data` | MySQL 数据文件 |
| `redis-data` | Redis AOF |
| `es-data` | 构建日志 / AI 审计索引（按日 `rp-exec-logs-YYYY-MM-DD`、`rp-assist-logs-YYYY-MM-DD`） |
| `backend-data` | `data/.secrets.json`、制品、上传的插件包、技能包、顶栏图片、Linux JDK 安装包（`shared-packs/jdk-linux/`）、对话上传文件 |

重建容器**不会**丢卷里的数据。`docker compose down -v` **会删卷**，等于清空这套环境。

## 6. 第一次登录后必须做的事

无论 A 还是 B。管理员进系统后按这个顺序，漏了后面会「助手不说话 / 脚本里地址不对 / 日志是空的」。

### 6.1 立刻改管理员口令

演示口令只适合本机。生产应在 `.env` 里设了 `BOOTSTRAP_ADMIN_PASSWORD`。若仍是 `admin123`：打开用户管理，改密。

### 6.2 配大模型（否则 AI Agent 不能用）

打开 **模型管理**（`/models`）。加一个 **OpenAI 兼容** 的厂商：

- API Base：例如 `https://api.deepseek.com/v1` 或你的网关 `/v1`
- API Key
- 再加一个模型名（与厂商控制台一致），设为可用

到 **AI Agent**（`/ai`）发一句「你是谁」，有流式回复才算通。

### 6.3 填写对外地址 `public_app_base`

打开 **平台设置**（`/settings`，仅管理员）。

**站点根地址**填用户浏览器里实际打开的地址，不要尾斜杠：

- 本机 Compose：`http://localhost:8000`
- 局域网：`http://192.0.2.10:8000`（改成平台机真实 IP）
- 域名：`https://deploy.example.com`

安装脚本、忘记密码邮件、部分跳转都认这个值。空着则用**当前这次请求**的 `Host`，多入口时容易装错地址。

### 6.4 Redis（Compose 已注入）

Compose 会把 `REDIS_HOST=redis`、`REDIS_PASSWORD` 传给后端。定时触发（流水线 cron）依赖 Redis 延迟队列。本机开发若没起 Redis，设置页里 Redis 保持空或 localhost，定时触发不会跑，其它功能仍可用。

### 6.5 Elasticsearch（Compose 已带上）

构建日志是 **Redis 实时 + ES 按日归档**，不能改回 MySQL。Compose 默认起本栈单节点 ES（`http://elasticsearch:9200`，不设账号），首次启动写入平台设置。

- 构建日志索引：`rp-exec-logs-YYYY-MM-DD`（上海时区自然日，可在设置页改前缀）
- AI 审计索引：`rp-assist-logs-YYYY-MM-DD`（固定前缀，不占用设置项）

要换自备集群：打开 **平台设置**，改 ES 地址 / 账号 / 索引前缀，保存即生效，不必重启后端。不要再用环境变量把地址锁死。

本机开发（A）没有 Compose 时，默认连 `http://localhost:9200`。可以另起一个同样的单节点，或暂时不装（历史日志空、健康页 ES down，发布仍能跑）。

Linux 宿主机若 ES 起不来，常是 `vm.max_map_count` 太小：`sysctl -w vm.max_map_count=262144`。

### 6.6 应急跳审保持关闭

设置里「应急跳过审批」默认关。新环境不要打开，除非你清楚分组级跳审的后果。

### 6.7 其它按需

LDAP、企微、SMTP、双因子、品牌名、顶栏图、会话天数：都在同一页，改完保存即可，不必重启后端。项的含义见第 15 节。

启动项只有这些，改了必须重启（或改 Compose `.env` 后 `docker compose up -d`）：

`DATABASE_URL`、`JWT_SECRET`、`AES_KEY`、`BOOTSTRAP_ADMIN_PASSWORD`、`CORS_ORIGINS`、`API_DOCS_ENABLED`

## 7. 装构建机

构建机执行 git 检出、编译、打包。平台「构建机」页（`/agents`）→ **新增构建机**，复制接入凭证和安装命令。命令已经带上当前的平台地址。

**新机器首次注册必须带接入凭证。** 登记成功后凭据在本机：

- Linux / macOS：`~/.release-agent/enrolled/`
- Windows 构建机脚本还会在 `C:\ProgramData\release-agent\builder\` 写启动器

之后重启、升级 jar 不必再带凭证。凭证泄露时在页面点「轮换接入凭证」；**已经登记的机器不受影响**。

### 7.1 Windows 构建机

本机已装 **能真正执行** 的 JRE/JDK 8+（只在 PATH 里留着卸载残留的 `javapath` 软链接不够）。以普通或管理员 PowerShell：

```powershell
iwr http://平台地址:8080/api/v1/agents/install-script?role=builder -OutFile install-agent.ps1
.\install-agent.ps1 -EnrollToken <页面复制的凭证>
```

若你是从平台页面下载的脚本，地址已填好。可选：

| 参数 | 含义 | 默认 |
|------|------|------|
| `-Server` | 平台根地址，含协议 | 脚本内回填 |
| `-Name` | 机器名，平台上唯一 | 计算机名 |
| `-Tags` | 调度标签，逗号或数组 | 按操作系统自动打 |
| `-Env` | `prod` / `test` / `uat` / `staging` / `dev` 或自定义小写码 | `prod` |
| `-Workspace` | 拉代码和产物的目录，**很吃磁盘** | 安装目录下的 workspace |
| `-Concurrency` | 同时跑几个任务，1～32 | 8 |
| `-WorkDir` | 安装目录 | `%USERPROFILE%\release-agent` |

C 盘紧张时务必：`-Workspace D:\rp-workspace`。

装完会建计划任务 **RELEASE-Build-Agent**：开机拉起，进程挂了约 2 分钟内自愈。平台发新 jar 后，构建机在**空闲**时自动升级。

`Env` 只在平台**第一次**见到这台机器时生效，之后以页面为准，避免重装冲掉人工改过的环境。

### 7.2 Linux / macOS 构建机

```bash
curl -fsSL "http://平台地址:8080/api/v1/agents/install-script?role=builder-linux" -o install-agent.sh
ENROLL_TOKEN=<页面复制的凭证> bash install-agent.sh
```

常用环境变量：`SERVER`、`NAME`、`TAGS`、`ENV`、`WORK_DIR`、`WORKSPACE`、`CONCURRENCY`。系统盘紧时：`WORKSPACE=/data/release-workspace`。

脚本会校验下载的 jar 与平台 `jar-sha256` 一致，对不上会删掉重来。

### 7.3 手工启动（调试）

```bash
java -jar deploy-agent.jar --server http://192.0.2.10:8080 --name linux-build-01 \
  --tags linux,maven,docker --enroll-token <凭证>
```

凭证也可用环境变量 `RELEASE_ENROLL_TOKEN`，避免写进 shell 历史。家目录可用 `RELEASE_AGENT_HOME` 覆盖，默认 `~/.release-agent`。

工作空间按流水线隔离：`--workspace` / `WORKSPACE` 根下 `p-{流水线id}/src/`。

装完到「构建机」页应显示在线。不在线见第 16 节。

## 8. 装部署节点

节点只做三件事：把文件写进白名单目录、还原备份、启停你允许的服务。白名单是安全边界：**空目录、盘符根、`/` 都不能当「全部」。**

接入凭证在「节点管理」（`/nodes`）→ **新增节点** 复制。

### 8.1 Windows 节点（IIS）

**必须以管理员身份**打开 PowerShell（启停应用池需要）：

```powershell
iwr http://平台地址:8080/api/v1/agents/install-script?role=node -OutFile install-node.ps1
.\install-node.ps1 -AllowPaths D:\wwwroot\mysite -EnrollToken <凭证>
```

| 参数 | 含义 |
|------|------|
| `-AllowPaths` | **必填**。允许写入的站点根，多个逗号分隔。只填站点，不要填 `D:\` |
| `-AllowIis` | 可选。再按应用池/站点名收紧；不填则按物理路径是否落在 AllowPaths 判断 |
| `-Env` | 默认 `prod`。`test`/`dev` 下发文件免审，其余要审。只在首次登记生效 |
| `-BackupRoot` | 备份根。必须在站点目录**之外**。留空则用站点所在盘的 `X:\release-backup` |
| `-WorkDir` | 安装目录，默认用户目录下 `rp-node` |

备份含 DLL 和 `web.config`，放进站点等于把连接串挂成静态文件。装完计划任务名 **RELEASE-Node-Agent**。

以后加允许目录：在「节点管理」改即可，心跳下发，不必重装。升级 jar：**不要**在节点上自作主张，到平台点「升级」，等当前发布跑完再换。

### 8.2 Linux 节点（systemd）

在节点上以 **root** 执行：

```bash
curl -fsSL "http://平台地址:8080/api/v1/agents/install-script?role=node-linux" -o install-node.sh
ALLOW_PATHS=/var/www/mysite ALLOW_SERVICES=systemd:nginx ENROLL_TOKEN=<凭证> bash install-node.sh
```

| 变量 | 含义 |
|------|------|
| `ALLOW_PATHS` | **必填**。允许写入的目录，逗号分隔。不要填 `/` |
| `ALLOW_SERVICES` | 允许控制的服务，如 `systemd:nginx,docker:web`。省略类型当 systemd。只拷文件不停服务可留空 |
| `RUN_USER` | Agent 运行账号，默认 `release`（没有会建，无登录）。可改成 `www-data` |
| `INSTALL_DIR` | 执行安装时所在目录。页面命令常带 `INSTALL_DIR=$(pwd)`。备份根取其第一层：`/data/soft/release` → `/data/release-backup` |
| `BACKUP_ROOT` | 显式指定备份根；不填则按上面规则推导，并 chown 给运行账号 |
| `ENV` | 同 Windows，默认 `prod` |
| `WORK_DIR` | 默认 `/opt/release-node` |

Agent **不以 root 跑**。需要停的服务走本脚本生成的 sudoers 白名单（`/etc/sudoers.d/release-node`），改启动参数也绕不开。

本机没有可用 Java 8+ 时，脚本用接入凭证从平台拉 JDK 8，校验 `java -version` 通过才继续；失败就退出，不会带着坏的 Java 把服务装上。平台侧要先上传安装包（第 9 节）。

systemd 单元名默认 `rp-node`。换平台地址后应重跑安装脚本（第 12 节），不要只改一个环境变量。

## 11. 生产加固与 HTTPS

### 11.1 清单

- `.env` 里试用口令只适合本机。对外服务请改成自己的长随机值后再部署。
- 不要用 `docker-compose.debug.yml` 把 3306/6379/9200 打到公网网卡。
- `API_DOCS_ENABLED` 保持关。
- 平台设置 `public_app_base` 为 `https://你的域名`。
- 管理员改密；按需要开 TOTP 双因子。
- 应急跳审保持关。
- Compose 已带 ES；自备集群到平台设置改地址。
- 后端 **单 worker**（镜像已如此）。定时触发是进程内线程，多 worker 会重复触发。多实例要共享同一份 `JWT_SECRET` / `AES_KEY` 和同一库，且不要跑多个调度。

### 11.2 外层 Nginx / 负载均衡（HTTPS 卸载）

浏览器只打到 443，反代到 Compose 的 **8000**（前端 Nginx 会再把 `/api` 转到 backend）。Agent 既可以走同一域名的 `/api`，也可以直连 8080；选一种写进 `public_app_base` 和安装脚本，不要混。

外层必须传：

```nginx
server {
    listen 443 ssl;
    server_name deploy.example.com;
    # ssl_certificate / ssl_certificate_key 按你的证书填写

    client_max_body_size 400m;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_buffering off;
        proxy_read_timeout 300s;
    }
}
```

漏了 `X-Forwarded-Proto`，安装脚本会回填成 `http://域名`，Agent 连上去被重定向或失败。

平台**不采信**客户端伪造的 `X-Forwarded-Host`。对外地址优先 `public_app_base`，没有才用请求 `Host`。

仓库自带的前端 Nginx 已处理：容器内只监听 80，会优先采信外层传来的 `https`，不会用容器自己的 `$scheme` 把 https 盖成 http。AI 对话是 SSE，反代不要打开 `proxy_buffering`，读超时至少 300 秒。上传插件 / 制品最大约 400 MB（`client_max_body_size`）。

### 11.3 CORS

Compose 下浏览器同源访问 8000，一般不用 CORS。若有人把前端和 API 拆到两个源，设 `CORS_ORIGINS`（逗号分隔，不要 `*`）并填 `public_app_base`。改 `CORS_ORIGINS` 要重启后端。

## 12. 换域名 / 换 IP

前端请求是相对路径 `/api/v1`，跟着浏览器地址栏走。通知里的站内链接也是相对路径。

**已装的 Agent 不会自己变。** 平台地址写死在启动器里：

| 系统 | 位置 |
|------|------|
| Windows 构建机 | 安装目录 `start-agent.cmd` 的 `--server` |
| Windows 节点 | `start-node.cmd` 的 `--server` |
| Linux 构建机 / 节点 | systemd 或启动脚本里的地址 |

正确做法：用**新地址**打开平台，重新复制安装命令，在每台机器上**重跑**。脚本覆盖启动器并重启。同名机器会更新原记录，ID、权限、历史保留，不会变成另一台。

登记凭据按「平台地址 + 机器名」分文件。地址一变就找不到旧凭据，会退回用接入凭证注册。页面上的命令已带凭证。

过渡期让新旧地址都通，切完再停旧地址。节点错峰切，避免发布做到一半 Agent 重启。

检查脚本回填的是不是新地址：

```bash
curl -s "https://新域名/api/v1/agents/install-script?role=builder" | grep -E "Server|RELEASE_SERVER|平台"
```

若仍是 `http://`，查外层是否传了 `X-Forwarded-Proto`，以及设置里 `public_app_base` 是否已改成 https。

再到构建机 / 节点页确认都在线。

## 13. 备份与恢复

至少备份这三样，缺一不可：

1. **MySQL**（卷 `mysql-data`，或 `mysqldump`）
2. **backend-data 卷**（密钥文件、制品、插件、JDK 包、品牌图）
3. **当时的 JWT / AES**（在卷里的 `data/.secrets.json`，或你写在 `.env` 里的值）
4. **es-data 卷**（构建 / AI 历史日志）。丢了只影响旧日志，流水线定义还在。

有 Redis 定时触发的，也可备份 `redis-data`；丢了只影响未触发的 cron，不会丢流水线定义。

示例（在 `deploy-platform/` 下，卷名可能带项目前缀，用 `docker volume ls` 核对）：

```bash
# 导出库（需能进 mysql 容器）
docker compose exec mysql mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" deploy_platform > backup-db.sql

# 备份数据卷：停服务再拷，或用 docker run --volumes-from
docker compose stop backend
# 把 backend-data 打成 tar 后放到安全的地方
docker compose start backend
```

恢复：先起 Compose，把 `.env` / `.secrets.json` 还原成**备份当时**那一套，再导入 SQL 和 `backend-data`。只还原库、不还原 AES，页面上的 Git 凭证全部解不开，只能重新录入。

`docker compose down -v` 会删除卷，等于销毁环境。

## 14. 升级

```bash
cd PekaFlowAI
bash deploy/pekaflow.sh upgrade
```

不要加 `docker compose down -v`。镜像更新后卷还在，密钥和库都在。代码已经拉过时用 `bash deploy/pekaflow.sh upgrade --skip-git`。

**改过 `agent-java/src` 必须重编 jar 再构建后端镜像**，否则平台继续下发旧 jar，源码和包名、环境变量会对不上。后端启动会比对 `deploy-agent.jar.srcsha` 与当前 Java 源码，不一致会打醒目警告。

```bash
cd deploy-platform/backend/agent-java
# Windows（需 JDK 8 的 javac）
build.bat
# Linux / macOS
./build.sh
```

产出 `deploy-agent.jar` 和更新后的 `.srcsha`，提交或至少放进构建上下文，再 `docker compose up -d --build`。

构建机空闲时会自己拉新 jar。节点要在平台上点「升级」。

## 16. 常见问题

1. **`python3` 无输出 / 退出码 49（Windows）**  
   用的是 Store 重定向器。改用 `py` 或虚拟环境里的 `python.exe`。

2. **后端日志 Access denied for user 'root'@'某IP' (1045)**  
   这是账号口令不对，不是网段不通（不通会是 timeout / connection refused）。`'root'@'20.10.6.4'` 里的 IP 是**后端连过来的来源地址**。`DATABASE_URL` 主机名必须是 `mysql`，不要填服务器局域网 IP。两处口令必须和 `MYSQL_ROOT_PASSWORD` 相同。若曾经用别的口令起过，数据卷还记着旧口令：空库可以 `docker compose down -v` 后重来（会清空库）。

3. **能打开前端，接口 401 / 跨域**  
   Compose 请走 8000 而不是直接拿 Vite 5173 去打生产后端。拆源时配 `CORS_ORIGINS` + `public_app_base`。

4. **管理员登不进去**  
   确认用的是 `BOOTSTRAP_ADMIN_PASSWORD`（若设过）。演示口令只在空库且未设该变量时存在。JWT 被换过则所有人要重新登录。

5. **助手一直转圈、没有字**  
   未配模型，或反代把 SSE 缓冲了 / 超时太短。查模型管理连通，Nginx `proxy_buffering off` 且 `proxy_read_timeout` ≥ 300s。

6. **定时触发不跑**  
   Redis 没起来或密码不对。试用默认 Redis 口令是 `rp-redis`。健康页看 Redis。

7. **执行历史没有日志**  
   ES 还在冷启动，或设置页地址不对。Compose 默认连 `http://elasticsearch:9200`。实时阶段看 Redis Stream；归档必须 ES。健康页会写 ES down。Linux 查 `vm.max_map_count`。

8. **构建机 / 节点一直离线**  
   机器要能访问 `--server` 那个地址（容器部署时不要填 `localhost`，那是节点自己）。核对接入凭证、防火墙、脚本里是否仍是 `http://` 而站点已是 https。Windows 看计划任务是否在跑；Linux 节点 `systemctl status rp-node`。

9. **安装脚本里平台地址是 http，站点是 https**  
   外层没传 `X-Forwarded-Proto`，或 `public_app_base` 没改。见第 11、12 节。

10. **Linux 节点下载 JDK 404**  
    未上传第 9 节的 tar.gz。

11. **jar 指纹不一致 / 启动警告 jar 和源码对不上**  
    改过 Java 没跑 `build.bat` / `build.sh`。重编后再构建后端镜像。

12. **虚拟机访问不到本机后端**  
    uvicorn 要 `--host 0.0.0.0`。`netstat` / `ss` 应看到 `0.0.0.0:8080`，不是 `127.0.0.1:8080`。

13. **SQLite 锁表**  
    开发偶发可忽略。完整试用和生产用 Compose 的 MySQL。

14. **bcrypt / `__about__`**  
    本项目用原生 `bcrypt`，不要再装一套 passlib 去覆盖。

15. **前端 build 报 `Cannot find module 'node:path'`**  
    `npm install -D @types/node` 后再 build。Compose 前端镜像已带依赖。

16. **海外构建前端镜像时 npm 很慢或失败**  
    前端 Dockerfile 默认 `registry.npmmirror.com`。可改成 `https://registry.npmjs.org` 后重新 `--build`。后端镜像默认阿里云 PyPI 镜像，同理可改。

17. **空发布清单报错、不肯打包**  
    这是设计：没写明文件列表就拒绝执行，不会变成全量包。把清单写在步骤里或当次填写。

18. **第三方 Agent 工具一律失败**  
    harness-runner 没起来，或 Token 与后端不是同一份。看 `docker compose ps` 里 `deploy-harness-runner`。本机开发不跑 Compose 时，第三方工具按失败关闭拒绝，不会在后端进程里执行。
