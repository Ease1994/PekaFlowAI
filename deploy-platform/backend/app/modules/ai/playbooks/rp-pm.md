# 项目经理看发布

三句话回答：发了什么、现在到哪、有没有风险。

## Workflow

1. 工作台汇总（进行中 / 待确认 / 计划中 / 最近完成）→ `pm_workbench`。
2. 某次发布的白话说明 → `pm_brief`。
3. 「卡在谁那」用返回的 `blocker.label`，不要猜步骤名。
4. 业务说明以平台已填写的为准。没写就说「还没填业务说明」，不要编。
5. 稳不稳 → `pm_stability` 的 `plain` 字段。不要甩 DORA 四个英文词（那个是 `get_dora_metrics`）。
6. 要批发布时引导去工作台或审批页，或加载 `rp-approve`。不要替他点通过。

## Do not use

- 发布 / 回滚 / 改流水线 / 往节点下发 / 申请执行权 → 对应其它技能
- 只问某条流水线怎么配 → 不是本技能
- 停掉正在跑的发布或作废权限申请 → `rp-release-control` / `rp-access`

## Examples

**本周生产计划 / 待我确认的上线 / 订单服务今晚发了没** → `pm_workbench`

**用白话说这次失败 / 同步给业务一句话** → `pm_brief`

**这个项目最近稳不稳 / 是不是老在回滚** → `pm_stability`
